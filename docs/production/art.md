# Codex 美术方向与交付合同

本页补充 [PRD10](../prd/10-art-audio.md)，把资产交到 Claude 手中时应有的文件、参数与验收写清楚。**当前全部游戏资产待制作；本次交付的是方案与清单。** 概念图、参考图和已导入可用资产必须分开标记。

## 1. 视觉方向

风格是柔软、可触摸的甜品玩具：圆润团子、水滴底形、略扁接触面，没有四肢；眼睛占身体高度18%～24%，表情用眼嘴完成。左上45°光源，柔和大高光加小高光，暖色接触阴影；描边取身体暗部再加深，不用纯黑。保留足够空地供单手拖动，不把画面塞满装饰。

主体基色直接读取 `config/flavors.csv`：Sugar `#EAF4FF`、Strawberry `#FF8FB1`、Cream `#FFF1D0`，后续Lemon `#FFE066`、Cocoa `#8B5A3C`。建议UI纸底 `#FFF8ED`、正文 `#513C38`、确认按钮 `#50745F`、警示 `#A74448`；这些UI色是初始美术值，导入后测对比度。按钮必须有文字/形状状态，不能只靠红绿区分可用性。

Sugar表现轻透、Strawberry表现果冻、Cream表现哑光奶油；原型只需可信材质差异，不以复杂折射阻塞D2。Berry Dots和Cream Swirl必须在灰度/色弱模拟下可区分。Shortcake靠蛋糕夹层与顶部草莓辨识；Cloud Puff靠云朵剪影，不能只改颜色。

## 4. 文件、坐标与导入协议

1. Codex交付 `art/source/<asset-id>/` 与 `art/export/<asset-id>_vNN.png`，角色/配件使用真实透明背景RGBA；不能用棋盘格假装透明。概念图标记 `reference_only`，不得放进运行时图集。
2. 身体、遮罩、高光都使用同一512×512画布，预留四边至少32px；身体中心pivot默认(0.5,0.5)，坐标从左下开始归一化。头顶/额头/侧面锚点按每种轮廓单独记录，不能凭视觉猜固定像素。32px是贴图留边，最大形变仍需Claude扩大网格包围盒并验证不裁切。
3. 色图按sRGB导入；遮罩/法线为数据贴图，关闭sRGB；遮罩黑0白1，边缘抗锯齿。同一资产层严禁各自紧裁切改变对齐。原型法线可暂不交，材质使用固定光照；不可把彩色生成图当法线。
4. Claude拥有Unity `.meta`、材质和prefab映射，替换纹理保留GUID；Codex拥有源图、输出图与视觉规格。先验证一套512源→256运行→128/64缩略图再批量导出。图集最大2048，ASTC压缩质量由真机对照确定，避免薄描边损坏。
5. 名称中的ID与CSV严格对应：`plain`是Sugar内部ID，不能自行改成`sugar`。拼装后的种类缩略图沿用PRD10的`sp_{body}_{swirl}`，招牌沿用`sig_*`。新资产ID与游戏数据ID的对应关系显式写表。
6. UI交付PNG外还要给9-slice边距、设计画布尺寸、最小可读字号/按钮触区、图标基线、选中/禁用状态。文字交Claude渲染并通过String ID取值；不把英文烘焙进按钮。
7. 声音提供无损源、游戏导出、时长/声道/峰值与来源；音效优先mono，音乐后续提供无缝loop点。没有授权或生成能力时标缺件；Claude可用明确标记的临时合成音验证输入，正式外测前替换并复核AB声音一致。

每次资产交付附一条记录（执行时建 `art/manifest.md`）：

```text
asset_id / batch / version / status(reference, draft, integrated, accepted)
source_path / export_path / runtime_mapping / dimensions / alpha / color_space
pivot / anchors / 9slice / animation_states / config_ids
source_or_generation_record / license_or_terms / attribution / review_status
sha256 / author / reviewed_build / reviewer / known_issues
```

采用生成图时，Codex保存提示词、工具/日期和参考来源，人工检查多余肢体、混乱高光、遮罩/分层可用性、与现有角色一致性。生成完成不代表可直接用于Unity，也不代表来源/授权审核自动完成；第三方字体、音频、图像同样需记录许可证与署名。商业授权未确认的素材不能进入商店RC。

## 5. 动作交接

Codex提供关键姿态、幅度/时序目标和情绪图；Claude实现弹簧/Shader/状态机并在设备调参。原型Bouncy用快起跳和明显回弹，Shy用短暂停顿、缩眼与小幅退缩；不能靠显示性格文字代替行为差异。两者都应允许即时输入反馈，性格延迟不可延迟手指响应。

时序沿用PRD：输入后首个可渲染帧响应，80～120ms形变峰值，≤500ms回弹；实际端到端延迟另测。A/B只切形变方式，声音、振动、表情、颜色、设备亮度和帧率目标保持一致。

## 6. 每批视觉验收

- 黑/白/棋盘底检查alpha、白边、漏裁切；64px原尺寸检查Body、Swirl与招牌轮廓；色弱/灰度对照检查形状差异。
- 静止、最大压扁、拉伸、局部凹陷时，花纹/眼嘴/头饰不漂移，锚点跟随变形；Cloud/Shortcake分别检查，不能只看普通圆形。
- 最低档iPhone同时4只动画、UI弹层和孵化效果时检查帧率与内存；不能只交一张精修静态图。
- 原型检查11种拼图；正式版检查29种及冻结范围内所有帽子组合。10人识别测试目标与判定沿用PRD10 Q1，单独记录样本、题目与正确率；不是E1的替代指标。
- Codex给视觉结论，Claude给实际渲染/性能结果；同一build留证据后标accepted。不能因PNG尺寸正确就标整批验收通过。
