**ENV-01 · 环境与构建通路（Claude + 负责人）**

- 输入：[CLAUDE.md](../../CLAUDE.md)、现有配置、Mac/iPhone/账号信息。
- 输出：`docs/production/environment.md`（执行时创建，含 Unity 精确补丁版本、URP/测试包版本、Xcode/macOS/iOS、Bundle ID、构建步骤与设备矩阵）；不记录凭据。Unity版本写入 ProjectVersion，包版本进入 lock 文件。
- 验收：Python现有检查通过；用临时空白探针工程验证实体iPhone安装启动（正式游戏工程由DEV-01建立）；环境配置有可复现步骤。Mac或签名缺失可做工程准备，但本任务整体保持BLOCKED，M0真机计时尚未开始。
- 技术路线：Unity 6 LTS / URP 2D，iOS 16+ / A12，C#逻辑层、uGUI或团队已验证UI栈，IL2CPP/ARM64/Metal。Claude 在此任务验证组合，不自行改引擎。Unity导出Xcode工程再构建iOS应用；本地最终构建需要macOS。[Unity官方流程](https://docs.unity.com/en-us/engine/6000.3/manual/platform-specific/iphone/getting-started/ios-environment-setup)

建议目录契约（由Claude创建并在实现后补全说明）：

```text
client/SlimeSweetsFarm/
  Assets/Game/{Domain,Application,Presentation,Infrastructure,Content,Tests}
  Packages/
  ProjectSettings/
art/source/                 Codex美术源/参考，不能直接当运行时资源
art/export/                 Codex已交付PNG/音频与资产记录
docs/production/evidence/   脱敏的执行报告（执行后创建）
config/                    正式设计数值，已有
tools/                     已有经济检查；新增导入/构建工具由Claude实现
```

逻辑层独立处理事务和计时；应用层组织命令；表现层订阅结果；基础设施层负责存档、平台接口与事件日志。无需为原型搭服务端或过度抽象。配置导入器明确错误行、ID与引用；未知ID、缺列、重复ID使构建失败。

## 6. PR与构建交付规则

- 一个PR围绕一个可验收行为或紧密依赖的小任务集；避免一次塞入全部P0。引用任务ID和PRD验收ID。
- 每个可安装构建记录 commit、Unity/Xcode版本、App版本/build、profile/config哈希、资产清单版本、设备与安装方法；留存符号文件以便解析崩溃。
- 配置导出后 `git diff` 应可解释，不能静默手改生成CSV。Python检查继续作为每个相关PR的基线；Unity EditMode/PlayMode、真机测试按变更范围增加。
- 没有Unity/iPhone访问条件时提交明确的 `NOT RUN` 与可复现步骤，不生成虚假的CI绿色截图；不为文档改动新建镜像式单元测试。
