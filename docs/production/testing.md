# 实际测试与证据门槛

本页定义“怎么测、谁来测、什么叫通过”。当前客户端测试、实体机测试、真人研究、TestFlight及App Store安装测试均为 **NOT RUN**；现有Python检查只证明配置与指定经济规则回放。

## 1. 测试分层

| 层次 | 执行者 | 重点 | 证据 |
|---|---|---|---|
| 配置/经济检查 | Claude，Codex复核规则 | CSV闭合、经济回放与边界 | 命令、退出码、完整日志、commit |
| Unity EditMode | Claude | 确定性培育、事务、退款、预留、时间、存档迁移、配置导入 | 测试报告与失败案例 |
| Unity PlayMode | Claude | UI输入、状态切换、教程恢复、场景与数据连接 | 自动化报告，必要录像 |
| 实体机功能/性能 | Claude在可控设备上执行，或负责人按脚本操作 | 触感、帧率、安全区、安装/升级、系统中断 | 设备/OS/build、操作记录、Profiler/Instruments数据、录像 |
| 真人研究 | 主持人与目标玩家；Codex分析 | 自主探索、推理、无奖励触摸、跨日偏好 | 固定脚本、匿名计数、干预与退出记录 |
| TestFlight/发行候选 | Claude + 真人测试者 | 实际签名包、外部安装、兼容、符号化崩溃、真实时间 | build号、测试范围、逐项结果、缺陷闭环 |

自动化、模拟器、助手自玩都不能填充正式用户样本。每项结果只能是PASS、FAIL、NOT RUN或BLOCKED；报告没有证据位置时不能写PASS。

## 2. 实体机矩阵与测试条件

| 设备组 | 用途 | 何时必须具备 |
|---|---|---|
| 最低档：iPhone XR/A12，实际支持的iOS版本 | 触摸、内存、帧率、冷启动；记录具体OS | M0至少最低档或接近档；M2/RC必须真实最低档，否则改变支持范围并重测 |
| 参考档：iPhone 12或同档 | 主要功能与对照 | M0开始前 |
| 当前主流大屏/刘海或灵动岛iPhone | 安全区、不同长宽比、最新稳定iOS | M3前；可借用，不要求提前购买 |
| 最低支持iOS 16环境 | 安装/兼容性与API回退 | M3前；模拟器先查，最终声明兼容需实际可用验证环境 |

设备可以覆盖多个组；不要求为了凑型号重复采购。没有设备的格子保持未测，不猜测通过。发行前另查实际启用的iPad兼容、Apple silicon Mac、Vision Pro可用性：不准备支持的可用性要正确配置；启用就纳入验证。

性能统一条件：相同亮度、声音/震动设置、关闭低电量模式、记录电量与热状态；正式测量不连接会显著改变结果的调试工具，开发包定位后再用接近发行的包确认。最低档连续15分钟：4只动画、喂食、拖拽、菜单、孵化循环；冷启动重复10次，排除首次资源初始化时单列而不隐藏。

目标沿用PRD11：交互60fps、最低档峰值内存≤350MB，最低档冷启动≤5秒/参考档≤3秒、离线计算≤50ms、包≤150MB。帧率报告P50/P95帧时、>33.3ms帧比例与持续掉帧片段；新增运行验收目标为稳定阶段P95≤20ms、>33.3ms帧占比<1%，场景首次加载另报。热降频失败时修复或正式降低支持范围，不能换高端设备掩盖。

触摸测量分两项：应用事件到首个渲染提交≤1帧；物理触摸到屏幕变化使用高帧率外部录像测量，报告采样帧率/误差与中位/P95，不把前者的16.7ms阈值套给后者。用实际帧序列检查80～120ms峰值和≤500ms回弹。

## 3. 必跑用例

| ID | 操作 | 判定 / 阶段 |
|---|---|---|
| T01 新档教学 | 全新安装按正常路径完成；另测误选/中断纠正 | 3分钟教学可达、结束基线90金币与正确饭碗；额外行为单列，不能硬重置资源；M0 |
| T02 自主培育 | 不领取额外赠币，教学后自行第二/第三次Start | 费用/亲本/容量按规则约束，无隐藏补贴；M0 |
| T03 原子性 | 不足金币/Treat、同亲本、亲本忙时点击Start；连点Start/Hatch | 不部分扣费、不重复发奖，Ready保留亲本锁，满位保留荚；M0 |
| T04 食物/容量 | 吃到一半换食；取消未吃与免费食物；一个罐满其余未满 | 只退未开始部分实付额；整份生产、预留一致；其他风味可推进；M0及正式全量 |
| T05 小屋/拥有 | 入屋、出屋、出售/放生、满容量、访客交付 | 屋内不生产；实际拥有才算访客；正式免费总容量覆盖29种；M0子集/M2完整 |
| T06 强退恢复 | 喂食后、订单交付后、Start扣费后、Ready、Hatch发奖时各强退重开 | 各至少1次、共至少5次，不重复扣费/发奖，不改变既定结果；M0；M2扩大随机时点 |
| T07 时间与后台 | 前后台/锁屏/来电打断；离线20分钟/8小时/24小时/7天；前拨/回拨/跨时区 | 前台与离线结果相符；7天截断、日重置/冻结符合PRD；M1起，真实过夜不能全用模拟时钟代替 |
| T08 存档故障 | 临时文件写一半、主档损坏、备份损坏、磁盘满、旧schema升级、新schema降级 | 恢复/提示符合PRD11，保留故障证据，无悄悄清档；磁盘满不显示保存成功；M2 |
| T09 显示与控制 | 最小/最大屏幕、系统文字尺寸、快速连点/多指、弹窗覆盖宠物、静音/关震动 | 关键按钮/数值可读可达，UI不穿透，开关有效，颜色之外也能辨识；M0子集/M2完整 |
| T10 网络/权限 | 飞行模式、弱网、拒绝通知、拒绝任何实际请求的权限 | 核心单机可玩；日志/配置重试不阻断；不需要ATT时根本不弹；M2 |
| T11 安装与升级 | 干净安装；上一测试版有进度→更新RC；重装与系统恢复分开测 | 升级保留宠物/货币/队列；重装无云存档的限制如实说明；系统备份恢复有单独证据；M3/RC |
| T12 正式包隔离 | 检查包内容、菜单、时间配置、网络域名与权限 | 没有研究夹具/无限金币/测试清档入口；无未声明SDK/测试服务器；M3/RC |

每次修复复测原问题+受影响的经济/恢复路径；改配置必须再跑全部配置检查与相应经济用例。只改文档不额外重跑整套真机测试。PRD12的其他完整产品用例由FULL-06建立映射，不被此摘要取代。

## 4. M0：12人研究

唯一人数与门槛来源为 [PRD14.4～14.5](../prd/14-two-week-prototype.md)，本页不重定义。12名未玩过本作的成年目标玩家，6人AB/6人BA，2名内部演练不计样本。D8/D9执行、D9/D10完成次日回访；负责人提前安排预约与研究同意。

固定流程：知情说明与设备检查→E1无奖励AB触摸→新档E2a教学→E2b自由探索5分钟→隐藏预览两道预测题→E2c独立Treat夹具8分钟→E4个体偏好→次日简短回访。正式记录姓名用随机编号替换。

主持人英文中性脚本建议：

> Try this version however you like. You may stop whenever you want.
>
> Please play from the beginning. I will observe without guiding you.
>
> You can keep playing for up to five minutes, or stop earlier.

进入预测题和招牌卡时再展示相应任务文字，禁止提前告诉玩家“你应该再培育两次”。求助记录时间与内容；必要帮助后保留样本，但对应独立完成项判失败。记录主动触摸区间、孵化时长、第二/第三次Start、预测答案、招牌尝试/提示、退出原因与个体偏好依据。

四项必要门槛全部通过才继续；一项失败可按PRD定向迭代一次，≥2项失败暂停扩展。关键体验改动后重收受影响项的新12人样本，不混版本。录屏仅作证据，公开仓库放脱敏计数；未经同意的声音/面孔不能上传。

## 5. M1：20人真实时间研究

这是后续内部决策门槛，**不是统计显著性或商业成功承诺**。M0通过后、招募前冻结方案。招20名未玩过本作的成年玩家，固定版本/配置，不用促回访通知或每日赠币刺激；完整观察每人安装后192小时。非留存触发的技术联系也要记录。

- D1定义安装后[24,48)小时内主动回到前台；D7为[168,192)小时。窗口按UTC计算，分母为20名有效首次启动者；缺席/退出不能删除。日志缺失标UNKNOWN，不能当未回访或剔除提高比例；技术失败可单独解释，但无法确认核心结果时不得判通过。
- 继续门槛：D1≥8/20、D7≥3/20；V1第二次≥14/20、24小时第三次≥10/20，口径按PRD12；V2/V4达到PRD12目标，报告实际合格分母。V2至少10人真实解锁并完成48小时观察机会；V4至少10人有合格无奖励会话，否则证据不足，不靠夹具补齐。
- V3跨日偏好逐人描述，不能用收藏/改名次数代替依恋；缺乏行为/声音偏好时可以继续改善免费体验，但不批准以依恋为依据的装扮商业化。
- 质量门槛：无未修复S0/S1；至少100个有记录的真实会话，所有崩溃和丢档逐项归因。该样本不能证明崩溃用户率<0.5%。
- 交付内容消耗分布（品种数/等级/到空目标所需时间）、缺钱/满罐/亲本忙卡点、放弃原因及修复建议。任何核心门槛未达则不自动扩完整P0，先记录是否迭代及新测试范围。

## 6. M3：TestFlight与RC

冻结招募目标50～100人及安装窗口，不能见到好结果就提前停样本；同一研究批次使用同一关键规则版本。D1/D7窗口同上，最后一人满192小时后出报告。研究目标沿PRD12：FTUE≥85%、D1≥40%、D7≥15%，同时检查V1/V2/V4，不以留存替代玩法指标；分母与未知日志单列。目标未达进入修复或延长研究决策，不能自动进入扩大推广。

RC退出条件：已冻结范围和全部关键功能用例通过；S0/S1为0，S2有明确处置与负责人接受记录；最小档性能通过；至少两台实体机完成干净安装、带进度升级和30分钟连续游玩；美术/音频授权与隐私材料齐全。报告所有观察到的崩溃数/用户数和缺失覆盖，不能将几十人零崩溃包装成达到长期0.5%目标。

RC和提交构建必须是同一个已验证build。重新打包、依赖变化、配置变化或资源替换后升级build号并复测受影响路径及安装/存档/核心流程；不得拿旧报告给新包背书。

## 7. 缺陷级别与证据

| 级别 | 示例 | 处理 |
|---|---|---|
| S0 | 数据泄露、普遍丢档、重复扣款（若后续接入） | 停止当前分发/扩量，先保存证据再修复；阻止发布 |
| S1 | 不能启动/安装、教学卡死、经济无法继续、关键按钮不可用 | 阻止外测或发行；修复并完整复测受影响流程 |
| S2 | 可绕过的局部错误、部分设备视觉遮挡、明显卡顿 | 定负责人、修复版与期限；影响核心研究则仍阻止该研究 |
| S3 | 不影响理解的轻微视觉/文案问题 | 列待办，不与阻断混淆 |

每条缺陷包括build/commit、设备/OS、profile、前置存档（受限）、操作步骤、预期/实际、发生频率、录像时间点、日志位置、修复PR与复测结果。日志导出仅含随机研究ID与必要游戏事件；可识别玩家的名称/联系方式删去或受限保存。负责人确定保存期限并告知测试者，阶段报告写清删除日期。
