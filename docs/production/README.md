# 从原型到 App Store：执行总计划

版本 1.0 · 2026-10-11 · 对象：项目负责人、Codex、Claude。

**分工：Codex 管计划与美术，Claude 写代码，负责人组织真实测试并决定发行。** 当前先执行10工作日原型；后续开发由验证结果逐阶段开启。本目录是未来执行流程，不表示客户端、资产、测试或上架已经完成。

## 2. 谁负责什么

| 工作 | Codex | Claude | 项目负责人/真人测试者 |
|---|---|---|---|
| 需求、数值、版本范围 | 主责，维护 PRD/配置与验收条件 | 评估实现成本，报告矛盾 | 决定资源投入、取舍与进入下一阶段 |
| 美术 | 主责：风格、概念、角色/场景/UI 资产、商店排版、视觉验收 | 制作导入器、材质、形变、动画、拼装预览工具，报告渲染约束 | 确认代表性样片；提供/购买已选授权素材 |
| 客户端代码 | 审核行为是否符合设计，整理问题 | 主责：工程、C#、Shader、原生桥接、数据、存档、工具、CI | 提供必要的构建设备与授权环境 |
| 自动化测试 | 给出判定口径与反例 | 编写/运行有意义的测试、修复、保存日志 | 可复核关键结果 |
| 真机与真人研究 | 测试脚本、数据解释、视觉与产品评审 | 测试包、诊断、性能测试、缺陷修复 | 实际持机操作、招募、同意记录、现场主持和访谈 |
| 上架 | 文案、截图设计、材料完整性检查 | Archive、签名配置、隐私技术清单、上传与审核修复 | Apple 账户、合同、身份/税务信息、最终商店声明及发布决定 |
| 上线后 | 分析反馈、排优先级、更新规格/美术 | 崩溃定位、修复、回归、新构建 | 客服、发行操作、账号维护 |

Codex 与 Claude 是工作角色，不等于已雇佣两位全职员工，也不保证无人值守持续工作。负责人把构建、评审意见和下一项任务在两者之间转交；每项工作都留下可接续记录。需要美术返工时，Claude 提供具体画面/尺寸/锚点问题，不能只写“需要美术”。

| M4 App Store 首次软启动 | 完整可用免费版本送审；明确地区；人工发布；实际商店安装检查 | 商店可下载、干净安装与升级路径通过；支持/隐私链接可用 | 审核通过时间不可承诺，不把提交当上线 |
| M5 运营与扩展 | 首日/首周问题处理，完整D7/D30观察；按证据再决定商业化/P1 | 留存与安全体验支持扩展、重新冻结下一版范围 | 独立计划；首发不承诺固定三周内容更新 |

首个公开版本采用不含 IAP/广告的完整免费范围；这与 PRD 的软启动1一致。商业化为 P0-M 独立版本；没有商店/广告 SDK 时也要完成真实隐私清单。M2默认以 PRD 12.4 候选P0为审查清单，任何删减（例如远程配置或通知）必须记录替代办法与受影响验收；不能默默删掉。

原文86～110程序人日是完整P0的历史工作量参考，不是 Claude 的工期承诺。M0结束时按已完成任务、真实阻塞、返工时间重新估算M1；每次只承诺下一阶段，明确工程时间、美术时间、真人测试窗口与外部等待。

## 4. 日常协作循环

1. Codex 把任务输入补齐：范围、验收、PRD链接、所需资产及版本。Claude 先看依赖，再实施代码和必要工具。
2. Claude 开任务分支 `claude/<task-id>-<description>`，提交可审查的小PR；提交可运行包/日志，而不只是代码片段。
3. Codex 按相同构建检查规则、视觉与手感证据；负责人/测试者完成设备操作。缺陷带复现步骤、预期/实际、设备、版本、严重度。
4. Claude 修复；复测受影响路径和关键经济/存档回归。通过后由有仓库权限的人合并，更新 [状态表](status.md)。普通可逆实现无需逐条等待口头确认。
5. 阶段结束填决策记录。没有真人测试数据时，最多标记“功能完成、验证待执行”，不自动进入下一阶段。

同一任务状态：`PLANNED → READY → IN_PROGRESS → REVIEW → VERIFIED`；缺输入为 `BLOCKED`，发现回归退回 `IN_PROGRESS`。`VERIFIED` 必须有对应任务的证据和执行者；上架则额外记录 `UPLOADED / IN_REVIEW / APPROVED / LIVE`，不可混用。

## 5. 必须提前准备的外部输入

| 输入 | 负责人动作 | 缺失时仍可做什么 |
|---|---|---|
| Mac或已授权macOS构建服务、Xcode、Unity iOS模块 | 提供可访问环境；付费服务需本人确定预算 | Claude 做 Windows 编辑器与纯逻辑，不能把真机门槛标通过 |
| 两台实体iPhone，至少一台A12/XR或真实最低档 | 记录型号、iOS、存储、电池状态；若拿不到最低档需缩小支持声明或保持待验证 | 模拟器验证布局，不能代替触感/性能结论 |
| Apple Developer Program及App Store Connect权限 | 本人注册、登录、2FA、同意合同；邀请必要角色 | 提前做构建/提交说明与材料草稿 |
| 测试者与主持人时间 | D1前预约12人；后续20人、50～100人另外招募 | 内部演练可以做，但不计正式样本 |
| 名称、客服邮箱、隐私网址、发行地区、素材预算 | 确认真实信息与授权证据；不使用猜测的公司名/邮箱 | Codex 写待填草稿和缺口清单 |

密钥、证书密码、2FA、测试者联系方式和原始录像放在受限位置。公开仓库只记录是否具备、负责人和证据编号，不提交敏感内容。上架前具体可审查材料由 Codex/Claude 先准备好，再由负责人完成账户声明和发布动作。
