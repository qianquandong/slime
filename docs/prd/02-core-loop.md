# 02 · 核心循环与目标

> 响应验收区分应用内输入事件→首次提交形变（目标≤1渲染帧）与物理触摸→屏幕显示的端到端延迟；后者单独测量，不直接套用16.7ms。两周范围以第14章为准。

## 2.1 系统连接总图

```
          ┌──────────── 触摸 Touch（揉/捏/抱）────────────┐

   ▲                 │                                                        │
   │                 └─连喂3次同一食物─► 表达风味 Showing ──┐                  ▼

   │                                                        ▼                  │

   │            │  费用(金币)+时间                                                │
   │            ▼                                                                  ▼
   │      新史莱姆（新品种→图鉴+经验+星星糖）                       订单 Orders / 柜台 Counter
   │            │                    │                                   │

                 │

```

| 系统 | 输入 | 输出 | 与谁相连 | 一句话作用 |
|---|---|---|---|---|
| 触摸 | 点击/长按/拖拽 | 形变反馈、亲密点、挤一挤原料、情绪 | 宠物状态、生产（前期） | 情感连接与前期启动资源 |
| 喂食 | 食物（金币） | 饭碗时长、连喂进度、亲密点 | 生产、培育 | 同一操作同时决定“产什么”和“亲本显什么色” |
| 生产 | 饭碗时长 | 原料（按品种匹配加成） | 储藏、厨房 | 离线收益来源 |
| 厨房 | 原料 | 甜品（即时） | 订单、柜台、培育Treat | 把原料变成可交付物 |
| 订单 | 甜品 | 金币、经验 | 等级、设施、培育费 | 主经济引擎 |
| 培育 | 两只亲本表达风味、可选甜品、金币 | 新史莱姆 | 图鉴、生产、访客 | 核心发现玩法 |
| 图鉴 | 首次孵化 | 经验、星星糖、线索 | 培育 | 告诉玩家“还有什么可以做” |
| 访客请求 | 拥有某外观的史莱姆 | 星星糖、经验、金币 | 培育 | 用外观描述驱动推理 |
| 布置/设施 | 金币、星星糖、等级 | 容量与效率 | 全部 | 长线目标；MVP 不含自由装饰编辑器 |

## 2.2 四个时间尺度的循环

### 10 秒循环：触摸

| 步骤 | 玩家做什么 | 游戏回应 | 目的 |
|---|---|---|---|
| 1 | 点一下史莱姆 | ≤16.7ms 局部凹陷，80～120ms 达到压扁峰值，≤500ms 回弹完成；表情变化；音效（音高随性格±、随连点上升）；轻震动 | 触感满足 |
| 2 | 连点 | 挤一挤环（Squeeze ring）填充 1/8；每次计入亲密（每只每天上限 20 次） | 小目标 |
| 3 | 第 8 下 | 弹出 1 个原料，飞入储藏罐（每只每天上限 10 个） | 前期资源；即时回报 |
| 4 | 长按 ≥1s | 拉伸+冒爱心=拥抱（每只每天 3 次计亲密） | 情感 |
| 5 | 狂点（任意 1 秒内第 7 次点击，即 >6 次/秒） | 晕眩 2.5s，期间仍有弱形变但不计亲密/挤一挤 | 防止把狂点当成最优策略，降低手部负担 |

### 3 分钟循环：一次打开

| 时间 | 玩家做什么 | 系统支持 | 产出 |
|---|---|---|---|
| 0:00 | 打开游戏 | 离线结算弹窗（While you were away）：原料数、到期孵化荚 | 回报感 |
| 0:10 | 孵化/命名 | 揭晓演出 2.5s（0.8s 后可跳过） | 新品种或重复 |
| 0:30 | 交付订单 | Bake & Deliver 一键；Deliver All | 金币、经验 |
| 1:00 | 看访客请求/招牌卡 | 外观描述+图鉴提示 | 下一目标 |
| 1:30 | 开始培育 | 选 Body/Swirl/Treat → 预览 → Start | 下一次回来的期待 |
| 2:15 | 一键加满饭碗 | Refill All（显示总价） | 离线产出保障 |
| 2:30 | 摸一摸最喜欢的那只 | 亲密进度 | 情感 |
| 3:00 | 离开 | 本地通知（已授权时）在孵化完成时提醒 | — |

### 1 天循环

| 内容 | 规则 | 设计意图 |
|---|---|---|
| 3～5 次打开 | 饭碗时长 2h（L1）→6h（L9）决定“多久回来一次不浪费” | 回访节奏可预期，不惩罚晚回来 |
| 每日任务（3 个） | 每个 30 金币+5 经验，全完成 +1 星星糖；L2 解锁 | 引导使用各系统 |
| 访客请求 | 每 6 小时来一位（L4 解锁） | 每天 ~2～4 个推理目标 |
| 亲密日上限 | 抚摸 20 / 拥抱 3 次 / 喂食 10 份计分 | 每天摸一会儿就“满了”，不鼓励长时间刷 |
| 激励广告 | 自愿，合计 ≤8 次/天 | 不成为必需 |
| 新解锁 | 到达等级的实际分布待多日测试，暂不承诺每日解锁频率 | 持续有新东西 |

### 长线循环：待真实时间验证

旧bot未完整约束显色、亲本占用、整份消化及活体持有，D7集齐/D14满级等输出已撤回，不能作为玩家进度下限。

| 阶段 | 需要验证的体验 | 证据要求 |
|---|---|---|
| 两周原型 | 无奖励触摸、理解规则、第二/三次主动培育 | 第14章12人协议；不推算长期留存 |
| 后续多日灰盒 | 普通矩阵是否快速失去吸引力；招牌造型/线索是否促成回访 | 真实计时、按安装日分组的7日游玩记录；记录离开原因 |
| 扩展P0前 | 宠物偏好是否跨日稳定，是否有足够内容维持目标周期 | 先验证再决定内容量；不能用日常任务或闪光刷取替代证据 |
| 扩展P1前 | 新风味与形态是否增加可感知变化 | 单独估工和小样本测试；不承诺软启动后3～4周更新 |

普通品种9/25格分别是原型/完整P0的收藏规模，不等于9/25个独立谜题。原型隐藏自动填槽Breed This，正式版是否开放及何时开放依据主动探索测试决定。

## 2.3 各系统在循环中的位置与“为什么需要它”

| 系统 | 若删除会怎样 | 结论 |
|---|---|---|
| 触摸形变 | 与其他放置游戏无差别 | P0 必需 |
| 连喂显色 | 培育变成“选两个品种”，失去“喂草莓变粉”的核心体验 | P0 必需 |
| 即时烘焙甜品 | 原料直接卖钱，经营层消失；与需求“甜品经营收入”不符 | P0 必需（但不做计时烤箱） |
| 订单 | 无经验来源与目标 | P0 必需 |
| 访客请求（探索订单） | 培育缺少“外观描述→推理”的外部驱动 | P0（简化版：1 个槽位） |
| 招牌配方 | 培育只有矩阵填格，缺少推理深度 | 候选P0（4个）；原型仅Shortcake/Cloud Puff两个 |
| 环境→形态 | 第三条外观轴 | P1 |
| 品种协作 | 布局策略 | P2 |
| 自由装饰编辑器 | — | 不做（需求明确排除大型编辑器）；P1 只做固定位置装饰 |

## 2.4 自动化之后，主动点击的意义

自动化来自三处：饭碗按时长消化（离线产出）、Refill All（一键加满）、Bake & Deliver / Deliver All（一键交付）。L3 之后，**不点击史莱姆也能推进主线**。点击的意义从“资源”转为以下 5 项：

| # | 点击带来的东西 | 规则 | 为什么不会变成刷点击 |
|---|---|---|---|
| 1 | 亲密等级 | 每次抚摸 +1 点（每只每天上限 20 点）；拥抱 +3 点（每天 3 次）；亲密 5 级 Best Friend：该只每份食物 +1 原料 | 每日上限；只对“你在意的那几只”有意义 |
| 2 | 个性反馈 | 6 种性格各有专属反应动画与音高；亲密 2/4 级解锁新互动反应 | 无数值收益，纯情感 |
| 3 | 挤一挤原料 | 8 次点击 = 1 原料，每只每天 ≤10 个 | 中后期价值很小（约等于 2～3 份食物产量），但能防死锁 |
| 4 | 闪光概率 | 亲本亲密等级之和每级 +0.5% 闪光率（上限 7%） | 只影响外观 |
| 5 | 触感本身 | 无奖励的形变、声音、连点音阶 | 这是产品支柱，不需要奖励驱动 |
