# 14 · 两周原型：范围、验证与决策

> v0.2 · 2026-10-11。当前计划执行的阶段为本章的 10 个工作日验证；其余章节 P0 是通过验证后的候选规格。本次 PR 只更新设计与检查工具，不包含可玩客户端。

## 14.1 要回答的问题

1. 没有资源、任务或亲密奖励时，触摸本身是否仍值得玩？
2. 玩家能否理解食物显色与 Body / Swirl，并主动开始下一个组合？
3. 能否区分并偏爱某个个体，而不仅仅点击初始宠物或最高产的宠物？两周只能观察偏好信号，不能证明长期依恋、留存或付费。

## 14.2 锁定范围

| 项目 | 两周交付 | 明确不做 |
|---|---|---|
| 场景 | 竖屏、一个围栏，最多4只可触摸；小屋为可选择的简单列表 | 多围栏、昼夜、场景装修 |
| 手感 | 一个共用身体网格，A缩放与B缩放+局部凹陷两版本；点击/长按/拖动；音效与震动开关 | 控制点软体、复杂碰撞、闪光、帽子 |
| 内容 | Sugar、Strawberry、Cream；3×3=9普通品种，Shortcake与Cloud Puff两个招牌，共11种；招牌有可辨剪影 | Lemon、Cocoa、完整29种、环境形态 |
| 个体 | 名字、收藏标记；Bouncy/Shy两种可辨反应（同一品种可不同）；情感测试时隐藏产量与稀有度 | 六种完整性格、亲密成长奖励、付费互动 |
| 培育 | 连喂3次显色；两只不同亲本；Body/Swirl预览、Swap、Start/Hatch；Treat、逐槽反馈、第三次未命中免费提示 | 自动填槽Breed This、Repeat Last、提示货币、多个窝 |
| 经济 | 简单金币/原料计数、饭碗队列、4款甜品（Cookie/Jelly/Puff/Shortcake）、一张固定可完成订单；使用第03/07章起点 | 随机订单板、访客调度、升级设施、每日任务、商业化 |
| 时间 | 首次培育30秒，第二次≤2分钟，第三次≤5分钟；招牌模块独立测试夹具给足原料，等候压至30秒并记录override | 用压缩时间数据推算真实回访或D7留存 |
| 数据/恢复 | 本地事件日志可导出、固定种子、步骤检查点；强退可恢复当前步骤与经济状态 | 云存档、远程配置、分析SDK、通知、正式迁移/备份管线 |
| 平台 | 已具备签名环境的一台最低档或接近最低档iPhone、一台参考档iPhone；线下真机测试 | App Store上线、广告/IAP接入、Android |

原型配置使用独立 profile，禁止覆盖 `config/*.csv` 的正式解锁等级；Treat与招牌测试通过主持人加载独立夹具，不能混入“自主第二次培育”的计数。只做足够判断触感与外观的美术，普通品种复用色板/遮罩。

原型教学使用第03章结束快照；其后等级保持L2，经验/星星糖/勺仅记录，不开放升级、任务或道具使用。第07章到L3的经济回放用于验证完整产品规则，不表示两周原型需要实现Lemon。Treat夹具独立开放4款甜品和2张招牌，不改变教学存档。

## 14.3 十个工作日与资源上限

假设仍为程序1、美术1、策划/测试1，各10人日；没有额外并行程序。D1前确认真机、签名和12名成年英语测试者可在D8–D10到场。若环境不具备，单独记录准备延误，不把它伪装成开发产能。

| 日 | 程序（10人日总额） | 美术 | 策划/测试与交付门槛 |
|---|---|---|---|
| D1–2 | 触摸输入、A/B形变、基础声音震动（2日） | 基体、3风味色板、2花纹 | 招募、测试脚本；D2真机可摸 |
| D3–4 | 显色、两槽培育/预览、孵化（2日） | 两招牌轮廓、2性格表现 | 验证槽位/亲本占用；D4核心链跑通 |
| D5–6 | 饭碗与经济最小链、短教学、步骤恢复（2日） | 简单场景和必要图标 | 执行经济回归；D6可从新档自主二次培育 |
| D7 | Treat反馈、事件日志、测试profile（1日） | 修复可读性 | 2名内部人员演练（不计正式样本）；冻结流程 |
| D8 | 真机阻断修复、测试支持（1日） | 修正触点/锚点 | 前6名正式测试；只修阻断，不中途改指标 |
| D9 | 预留修复/重测（1日） | 测试支持 | 后6名及次日简短回访 |
| D10 | 预留数据核对/补测（1日） | 整理对照录像 | 逐人结果、问题排序、继续/迭代/暂停决定 |

砍项顺序：独立厨房页→合并为订单按钮；小屋排序/改名界面→固定名字与收藏按钮；装饰性演出→简单揭晓。不得砍：B局部形变、显色/槽位规则、经济约束、无奖励触摸、日志与完整测试。D4未跑通核心链或D6仍有经济阻断，则冻结新增内容，D10交付失败原因与下一轮范围，不宣称通过。

## 14.4 测试协议与通过标准

正式样本固定12名未玩过本作的成年目标用户；内部演练不计入。中途退出计作该流程未完成，崩溃单独记录；仅设备/预约失败可补招。逐项报告分子/分母，不以小样本宣称统计显著。以下阈值都是立项假设。

冻结后如修复改变触感、经济或引导，受影响项必须在同一版本重新收齐12名新测试者；不得合并前后版本凑数。D10尚未收齐则交付“验证待完成”，不降低阈值。

| 问题 | 流程与计数口径 | 通过阈值 |
|---|---|---|
| E1 触感差异 | A/B各先熟悉15秒，再进入最多90秒中性自由触摸期，6人AB/6人BA；仅形变不同，音效/震动条件一致。均无金币、亲密、任务奖励，随时可退出；两个版本都结束后才二选一 | ≥9/12偏好B；B中性自由期主动触摸时长中位数≥30秒。主动时长取按住区间与相邻≤2秒触摸间隔的并集，不重复累计，不计长时间无输入 |
| E2a 教学可理解 | 从新档开始，不口头指导；教学目标≤3分钟首次孵化。预测题放在E2b自由探索之后：隐藏预览，给两个教学未演示过的槽位组合，各预测一次，避免题目提前指定探索目标 | ≥10/12在3分钟内孵化；≥10/12两题均正确；求助或主持人代操作计未独立完成 |
| E2b 主动探索 | 教学完自由玩5分钟，不弹任务、奖励推荐或指定配方；允许提前结束。第二次培育的计时上限2分钟，费用不免 | ≥8/12主动开始第二次培育；≥6/12在窗口内主动开始第三次；单独记录“资源不足/不知道做什么/不想继续”，不以降低价格掩盖动机问题 |
| E2c 招牌推理 | E2b及隐藏预览预测题之后加载独立Treat夹具，最多8分钟；随机分配首张招牌、顺序各6人，第二张只作迁移观察 | 首张≥8/12在无免费揭示/主持人提示前解出且能解释线索；成功者尝试中位数≤3。未解出人数必须同时报告，免费提示后的成功另列 |
| E4 初步个体偏好 | 最后给3只同龄同品种、无产量差异的宠物，随机位置/名字与性格对应；3分钟自由互动后问最想留下谁及原因，次日回访是否记得 | 探索项：≥6/12能指出行为/声音/互动理由且次日记得选择。仅颜色偏好、第一只、任务引导单列；不作为长期依恋已经成立的证据 |

无奖励触摸段禁止出现挤一挤环、亲密进度、每日任务、金币变化；教学与经济段的触摸不计E1。E2b开始前保存并对照第03章标准快照（预测题尚未开始），额外触摸所得或纠正路径的差异单列，不能覆盖玩家所得或剔除困难样本。主持人只读统一脚本；所有帮助记录时间与类型。

## 14.5 功能验收与决策

交给外部测试前：真机无阻断；按下后首个可渲染帧开始响应（应用内输入→提交渲染≤1帧，物理触摸→屏幕延迟另测，不混为同一指标）；首帧起80–120ms形变峰值、≤500ms回弹；经济检查及回归全部通过；5次强退恢复不重复发奖；满碗可通过明确的Swap Snack准备新风味；孵化满容量保留荚；原型不会实际扣款。

| 决策 | 条件 | 后续承诺 |
|---|---|---|
| 继续 | E1、E2a、E2b、E2c全部通过，且无经济/存档阻断 | 批准下一轮灰盒与真实时间的多日测试；重新估工，不自动批准完整P0 |
| 定向迭代一次 | 其中一项未达标且有明确可修复原因 | 最多追加5工作日，只修对应问题，用新的12人复测失败项及受影响流程 |
| 暂停扩展 | 两项及以上未达标，或一次定向复测仍未过 | 停止扩内容/商业化；记录失败假设，重新决定产品方向 |

E4未达标时，即使其他项通过，也不能批准以宠物依恋为依据的装扮商业化；先加强个体行为并做多日验证。D1/D7/D30、付费率、三周更新产能均不在本次通过声明内。

交付物：可安装原型、锁定profile与版本号、12人逐项匿名计数、带override/奖励状态的事件日志、关键录像、按阻断程度排序的问题表、一页决策记录。没有真机用户测试数据时只能写“原型功能完成，验证待执行”。
